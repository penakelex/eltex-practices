# Task 3: POSIX Message Queues + Signals

Чат на очередях сообщений POSIX (`mq_open(3)`). Один процесс-владелец
создаёт две очереди `<name>_1` и `<name>_2`; к нему подключаются
процессы-peers, каждому присваивается имя `peer1`, `peer2`, ... в порядке
подключения. Владелец видит, от какого именно peer'а пришло сообщение,
а рассылка владельца доходит до всех peers.

## Возможности

- **Две очереди на сессию.** К имени из аргументов добавляются суффиксы
  `_1` и `_2`. Кто первым создал первую очередь (`O_CREAT | O_EXCL`), тот
  владелец: принимает через `_1`, отправляет через `_2`. Первый peer
  отправляет через `_1` и принимает через `_2` — ровно как описано в
  задании для двухпроцессного сценария.
- **Несколько peers.** Очередь `_2` обслуживает только первого peer'а,
  поэтому каждый следующий peer при старте создаёт свою приватную очередь
  `<name>_p<pid>`. POSIX mq — point-to-point: сообщение из общей очереди
  получает ровно один читатель, «рассылки» на одной очереди не существует.
  Приватные очереди peers позволяют владельцу доставлять сообщения каждому.
- **Нумерация по порядку подключения.** При подключении peer отправляет
  `hi,<pid>`; владелец отвечает `you,<pid>,peer<N>`, где `N` — номер
  подключения. Ответ идёт через `_2` для `peer1` и через приватную очередь
  для остальных. Ожидание ответа — до 5 секунд, иначе `No owner answered`.
- **Идентификация сообщений.** Сообщения peers содержат pid отправителя,
  владелец печатает `peerN> текст`. Peers печатают сообщения владельца как
  `owner> текст`.
- **Асинхронный обмен.** Один цикл `poll(2)` на stdin и дескрипторы
  принимающих очередей (`O_NONBLOCK`).
- **Корректное завершение.** Обычные сообщения идут с приоритетом 0,
  уведомления об уходе — с приоритетом `chat_quit_priority` (8). Уход
  peer'а (`bye,<pid>`) удаляет его из списка владельца, остальные не
  замечают. Уход владельца (`bye`) завершает всех peers. Очереди `_1`/`_2`
  удаляет владелец, приватную очередь — её создатель.
- **SIGINT/SIGTERM.** Обработчик только ставит флаг `volatile
  sig_atomic_t`; главный цикл (poll прерывается без `SA_RESTART`) шлёт
  уведомление об уходе и завершается.
- **Ctrl-D** (EOF на stdin) — штатный уход, аналогично сигналу.

## Архитектура

- `main.c` — разбор `argv`: `./mq_chat <queue_name>`; валидация имени
  (алфавитно-цифровые символы, `_`, `-`), префикс `/`.
- `chat/chat.c` — точка входа `chat_run()`: определение роли, общий хелпер
  отправки.
- `chat/chat_owner.c` — роль владельца: таблица подключённых peers, цикл
  poll, регистрация, рассылка каждому peer'у.
- `chat/chat_peer.c` — роль peer'а: регистрация (`hi`/`you`), цикл poll,
  обработка сигналов.
- `chat/chat_internal.h` — приватный интерфейс между единицами чата.
- `mq_queue.c` — открытие пары `_1`/`_2` и определение роли, создание
  приватной очереди peer'а, закрытие и удаление.
- `protocol.c` — формирование и разбор кадров `hi`, `you`, `msg`, `bye`.
- `signal_state.c` — общий флаг завершения и `sigaction`.
- `view.c` — весь вывод в `stderr`/`stdout`.
- `tests/test_mq_queue.c` — Unity-тесты обёрток над очередями и протокола.

### Протокол

Очередь `<name>_1` (peers → владелец), приоритет 0:

```
hi,<pid>
msg,<pid>,<text>
```

Очередь `<name>_1`, приоритет `chat_quit_priority`:

```
bye,<pid>
```

Очередь `<name>_2` (владелец → peer1), приоритет 0:

```
you,<pid>,peer<N>
msg,<text>
```

Очередь `<name>_2`, приоритет `chat_quit_priority`:

```
bye
```

Приватная очередь `<name>_p<pid>` (владелец → peerN, N ≥ 2): те же кадры
`you`/`msg`/`bye`, что и для `_2`.

## Использование

```bash
make
./build/bin/mq_chat demo        # терминал A — владелец
./build/bin/mq_chat demo        # терминал B — peer1
./build/bin/mq_chat demo        # терминал C — peer2
```

Через `make` (из `module3`):

```bash
make run-03 ARGS="demo"
```

Пример сессии:

```
# B: привет                    →  A печатает: peer1> привет
# C: всем привет               →  A печатает: peer2> всем привет
# A: добро пожаловать          →  B и C печатают: owner> добро пожаловать
# B: Ctrlmg-D                    →  A печатает: peer1 left the chat
# A: Ctrl-C                    →  C печатает: Owner left the chat и выходит
```

После ухода владельца очереди `/dev/mqueue/demo_1` и `demo_2` удалены.

## Тестирование

```bash
make test               # Unity-тесты
make test-integration   # владелец + два peer'а: нумерация, рассылка, уходы
```

Интеграционный сценарий (`tests/run_integration.sh`) проверяет:

- владелец видит `peer1> ...` и `peer2> ...` в порядке подключения;
- рассылка владельца доходит до обоих peers;
- уход `peer1` сообщается владельцу по имени, владелец продолжает работу;
- уход владельца завершает оставшегося peer'а;
- очереди `_1`/`_2` удалены.

## Зависимости

- C23-совместимый компилятор (`clang` по умолчанию).
- POSIX.1-2024: `mq_open(3)`, `mq_send(3)`, `mq_receive(3)`,
  `mq_close(3)`, `mq_unlink(3)`, `poll(2)`, `sigaction(2)`; линковка с
  `-lrt`.
- `curl` — только для первой загрузки Unity при `make test`.

## Ограничения

- Очереди создаются с атрибутами по умолчанию (`mq_maxmsg` 10,
  `mq_msgsize` 8192); переполнение при отправке диагностируется через
  `mq_send: Resource temporarily unavailable`.
- `SIGKILL` владельца не перехватывается: очереди остаются в
  `/dev/mqueue` и чистятся вручную (`rm /dev/mqueue/<name>_1 ...`).
- Peers не узнают о внезапной смерти владельца, кроме таймаута
  регистрации при подключении.
- Приватные очереди умерших peers (`<name>_p<pid>`) остаются в
  `/dev/mqueue`, пока peer не завершился штатно; новый peer с тем же pid
  пересоздаёт свою очередь.
