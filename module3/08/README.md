# Задание 8. Перехват UDP-сегментов через RAW-сокеты

Программа получает копии UDP-сегментов через сокет
`socket(AF_INET, SOCK_RAW, IPPROTO_UDP)` и позволяет выбрать фильтр
захвата:

- `chat` — сообщения программы из задания 6 (UDP-чат); порт задаётся
  опцией `-p` (по умолчанию 4000), совпадает с портом запуска чата;
- `dns` — чужой трафик DNS (UDP-порт 53); для запросов дополнительно
  извлекается и выводится имя домена;
- `dhcp` — DHCP (порты 67/68);
- `ntp` — сетевая синхронизация времени (порт 123);
- `mdns` — multicast DNS (порт 5353);
- `quic` — QUIC/HTTP3 (порт 443);
- `all` — все UDP-сегменты без фильтрации.

Фильтры комбинируются через запятую в одном `-f`, например
`-f dns,chat,ntp` захватывает сегменты, попадающие хотя бы под один из
перечисленных фильтров.

Для каждого захваченного сегмента выводятся: время с начала захвата,
MAC-адреса отправителя и получателя, IP-адреса и UDP-порты отправителя
и получателя, длина полезной нагрузки.

MAC-адреса восстанавливаются без Ethernet-заголовка: собственный MAC
интерфейса — через `getifaddrs`, MAC удалённых хостов — из ARP-кэша
(`/proc/net/arp`), для широковещательных адресов выводится
`ff:ff:ff:ff:ff:ff`. Если MAC неизвестен (например, запись в ARP-кэше
ещё не появилась), выводится `??`.

## Сборка и тесты

```
make
make test
```

## Запуск

RAW-сокет требует прав root или capability `CAP_NET_RAW`:

```
sudo ./build/bin/udp_sniffer -f dns -o capture.txt
sudo ./build/bin/udp_sniffer -f chat -p 4000
sudo setcap cap_net_raw+ep ./build/bin/udp_sniffer   # альтернатива sudo
```

Сеанс захвата завершается по Ctrl+C (SIGINT), после чего собранные
сегменты выводятся на экран и, при указании `-o`, сохраняются в файл.

Пример строки результата:

```
+   12.345s MAC aa:bb:cc:dd:ee:ff -> ff:ff:ff:ff:ff:ff IP 192.168.1.2:4000 -> 192.168.1.255:4000 len=42
```

## Проверка вместе с wireshark

Для отчёта: запустить захват (`-f dns`), в соседнем терминале выполнить
`dig example.com`, остановить захват и сравнить сегменты с выводом
wireshark (фильтр `udp.port == 53`) — порты, адреса и длины должны
совпадать. Аналогично для чата из задания 6 (`-f chat -p <port>`).
