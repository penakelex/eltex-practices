# Task 1: File Copy via fork + Pipes

Копирование файлов, разделённое между родительским и дочерним
процессами. Обмен идёт по двунаправленному каналу: неименованные
`pipe()` по умолчанию либо пара именованных FIFO при `-p`. Каждый
файл `name` превращается в `name.copy` в текущей директории.

## Возможности

- **Два режима каналов.** Без `-p` — два неименованных `pipe()`; с
  `-p <base>` — два FIFO: `<base>.p2c` (parent → child) и
  `<base>.c2p` (child → parent).
- **Двусторонняя синхронизация.** Дочерний процесс шлёт родителю байт
  готовности (`'R'`), только после этого начинается передача.
- **Пакетная передача.** Для каждого файла родитель шлёт заголовок
  `[uint32 name_len][name][uint64 size]`, затем данные блоками по
  `FILE_COPY_BLOCK_SIZE` (4096) байт.
- **Множество файлов.** Файлы передаются последовательно; сигналом
  завершения служит заголовок с `name_len == 0`.
- **Пропуск проблемных файлов.** Несуществующий, не-регулярный или
  слишком длинный файл не роняет процесс — в `stderr` выводится
  диагностика, остальные файлы копируются.
- **Устойчивость к `SIGPIPE`.** Если ребёнок умер, родитель получит
  `EPIPE` из `write` и корректно завершится.

## Архитектура

- `main.c` — разбор `argv` (`[-p base] file...`), запуск `file_copy_run`.
- `file_copy.c` — оркестрация: инициализация канала, `fork`, `waitpid`,
  обработка `SIGPIPE`.
- `file_copy_channel.c` — создание/закрытие/освобождение каналов
  (неименованных и именованных), `mkfifo`, `unlink`.
- `file_copy_io.c` — блокирующие `file_copy_read_full` /
  `file_copy_write_full` (обрабатывают `EINTR` и частичные операции) и
  кодирование заголовков (`file_copy_write_header` /
  `file_copy_read_header`).
- `file_copy_parent.c` — родитель: открытие и `stat` источника,
  передача заголовка и блоков, финальный заголовок-завершение.
- `file_copy_child.c` — ребёнок: открытие канала, байт готовности,
  приём заголовков и блоков, запись `.copy`.
- `view.c` — весь вывод в `stderr` (usage, ошибки `open`/`stat`/`create`,
  не-регулярный файл, слишком длинное имя).
- `include/file_copy.h` — публичный API (`FileCopyOptions`,
  `file_copy_run`, функции протокола для тестов).
- `include/view.h` — интерфейс слоя представления.
- `src/file_copy/file_copy_internal.h` — приватный заголовок с типом
  `FileCopyChannel` и внутренними объявлениями.

### Протокол обмена

```
child                         parent
  |  open(to_child, O_RDONLY)   |
  |  open(to_parent, O_WRONLY)  |
  | ----- 'R' (1 byte) -------> |  readiness
  |                             |
  | <--- [name_len][name][size] |  header
  | <--- [data block]*          |  blocks
  |                             |
  | <--- [name_len][name][size] |  next file
  | <--- [data block]*          |
  |          ...                |
  | <--- [0][0]                 |  termination
```

## Использование

```bash
make
./build/bin/file_copy [-p fifo_base_name] file1 [file2 ...]
```

Примеры:

```bash
# Неименованные каналы
./build/bin/file_copy file1.txt file2.txt

# Именованные каналы
./build/bin/file_copy -p /tmp/copyfifo file1.txt

# Через make
make run-01 ARGS="file1.txt file2.txt"
make run-01 ARGS="-p /tmp/copyfifo file1.txt"
```

Ошибочные сценарии:

```bash
./build/bin/file_copy
# Usage: ./build/bin/file_copy [-p fifo_base_name] file1 [file2 ...]

./build/bin/file_copy -p
# Usage: ./build/bin/file_copy [-p fifo_base_name] file1 [file2 ...]

./build/bin/file_copy missing.txt file1.txt
# Cannot open 'missing.txt': No such file or directory
# (file1.txt всё равно копируется)
```

При некорректных аргументах и при неустранимых ошибках канала или
протокола программа возвращает `EXIT_FAILURE`.

## Тестирование

```bash
make test               # Unity-тесты протокола
make test-integration   # end-to-end bash-скрипт
```

**Unity-тесты** (`tests/test_file_copy.c`) покрывают заголовочный
протокол:

- roundtrip заголовка (имя и размер);
- заголовок-терминатор (`nullptr`);
- пустое имя как терминатор;
- имя длиннее буфера → ошибка разбора.

**Интеграционный скрипт** (`tests/run_integration.sh`) прогоняет
полные сценарии на реальных файлах:

- одиночный файл через неименованный канал;
- несколько файлов (включая бинарный) через неименованный канал;
- одиночный файл через именованный канал;
- несуществующий файл в списке — остальные копируются, в `stderr`
  есть диагностика;
- запуск без аргументов и с `-p` без имени — отклоняются.

Каждый сценарий проверяет, что `.copy` создан и совпадает с
оригиналом (`diff`).

## Инструменты

- `make` — собрать `build/bin/file_copy`.
- `make test` — Unity-тесты.
- `make test-integration` — end-to-end сценарии.
- `make clean` — удалить `build/`.

Форматирование проверяется общими целями из `module3/Makefile`:
`make -C .. format` и `make -C .. format-check` (требуется
`clang-format`).

## Зависимости

- C23-совместимый компилятор (`clang` по умолчанию, переопределяется
  через `make CC=gcc`).
- POSIX.1-2024: `pipe(2)`, `mkfifo(3)`, `fork(2)`, `waitpid(2)`,
  `open/read/write/close`.
- `curl` — только для первой загрузки Unity при `make test`.

## Ограничения

- Передаются только регулярные файлы (не каталоги, не устройства).
  Не-регулярный файл пропускается с диагностикой.
- Имя файла ограничено `FILE_COPY_MAX_NAME_LENGTH` (4096) байт.
- Размер файла берётся из `fstat(2)` и не меняется во время передачи;
  если файл растёт/усекается параллельно, копия получится неполной
  или с ошибкой чтения — это ожидаемо.
- Именованные FIFO создаются с правами `0600` и удаляются при
  завершении; если процесс убит `SIGKILL`, FIFO останутся — следующий
  запуск перезапишет их.
- Содержимое `.copy` не сравнивается с оригиналом по хешу; проверка
  корректности — через `diff` в интеграционном скрипте.
