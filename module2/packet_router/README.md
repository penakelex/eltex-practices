# Packet Router

Имитация принятия решения при отправке IPv4-пакетов по сети. Программа
генерирует случайные IP-адреса назначения и для каждого определяет,
принадлежит он подсети шлюза или нет. По итогам обработки выводится
статистика распределения пакетов.

## Возможности

- **Разбор IPv4.** Адрес шлюза и маска подсети задаются в стандартной
  точечно-десятичной нотации (`192.168.1.1`, `255.255.255.0`) и валидируются
  через `inet_pton(3)`.
- **Случайные пакеты.** Генерируется ровно `N` случайных 32-битных адресов
  назначения (по 16 бит из двух вызовов `rand()`).
- **Определение подсети.** Принадлежность считается по классической формуле
  `(ip & mask) == (gateway & mask)` — без обращений к сети, всё в памяти.
- **Статистика.** Выводятся количество и процент пакетов, предназначенных
  узлам «своей» подсети, и пакетов для других сетей.
- **Валидация аргументов.** Некорректный IP, маска или `N ≤ 0` дают понятную
  ошибку и ненулевой код возврата; программа не падает.

## Архитектура

- `packet_router.c` — бизнес-логика:
  - `packet_router_run` — основной сценарий: парсинг аргументов, генерация
    пакетов, подсчёт статистики;
  - `packet_router_is_same_subnet` — чистая функция проверки принадлежности
    подсети (удобна для тестов);
  - `packet_stats_initialize` / `packet_stats_free` — работа со структурой
    `PacketStats`.
- `view.c` — весь вывод в консоль: справка, сообщения об ошибках, статистика.
- `main.c` — разбор `argv`, запуск сценария, обработка статуса.
- `include/packet_router.h` — публичный интерфейс логики и тип статуса
  `PacketRouterStatus`.
- `include/view.h` — интерфейс слоя представления.

### Статусы

| Статус                             | Причина                                      |
|------------------------------------|----------------------------------------------|
| `PACKET_ROUTER_OK`                 | успешная обработка                           |
| `PACKET_ROUTER_INVALID_GATEWAY`    | не удалось разобрать IP шлюза                |
| `PACKET_ROUTER_INVALID_MASK`       | не удалось разобрать маску подсети           |
| `PACKET_ROUTER_INVALID_PACKET_COUNT` | `N` равно нулю или выходит за `uint32_t`    |
| `PACKET_ROUTER_INVALID_ARGUMENTS`  | передан `nullptr` в обязательный параметр    |

## Использование

```bash
make
./build/bin/packet_router <gateway_ip> <subnet_mask> <packet_count>
```

Пример:

```bash
./build/bin/packet_router 192.168.1.1 255.255.255.0 1000
```

Вывод:

```
Total packets: 1000
Packets to own subnet: 392 (39.20%)
Packets to other networks: 608 (60.80%)
```

Ошибочные сценарии:

```bash
./build/bin/packet_router 192.168.1.1 255.255.255.0 0
# Error: packet count must be positive.

./build/bin/packet_router 192.168.1.256 255.255.255.0 10
# Error: invalid gateway IP address.

./build/bin/packet_router 192.168.1.1 255.255.255.0
# Usage: ./build/bin/packet_router <gateway_ip> <subnet_mask> <packet_count>
```

При неверных аргументах программа возвращает `EXIT_FAILURE`.

## Тестирование

```bash
make test
```

Фреймворк **Unity** скачивается автоматически при первом запуске тестов в
`../third_party/Unity/src` (общий для всех модулей `module2`). Тестовая сборка
изолирована от основной (`build/test/`), `src/main.c` в неё не попадает.

Покрыто:

- проверка принадлежности подсети: адрес внутри и адрес вне диапазона
  (граничные случаи `192.168.1.x` против `192.168.2.x`);
- инициализация структуры `PacketStats`;
- валидация аргументов: `nullptr` в каждом из параметров, `N = 0`,
  некорректные IP шлюза и маски;
- граничный случай с маской `0.0.0.0` — все пакеты должны попасть в «свою»
  подсеть (проверяется, что `local_packets == total_packets`,
  `foreign_packets == 0`).

## Инструменты

- `make` — собрать приложение `build/bin/packet_router`.
- `make test` — собрать и запустить юнит-тесты.
- `make clean` — удалить каталог `build/`.

Форматирование проверяется общими целями из `module2/Makefile`:
`make -C .. format` и `make -C .. format-check` (требуется `clang-format`).

## Зависимости

- C23-совместимый компилятор (`clang` по умолчанию, переопределяется через
  `make CC=gcc`).
- POSIX.1-2008: `inet_pton(3)` из `<arpa/inet.h>`.
- `curl` — только для первой загрузки Unity при `make test`.

## Ограничения

- Генерируются только адреса IPv4; IPv6 и CIDR-нотация (`/24`) не
  поддерживаются — маска задаётся отдельным аргументом в точечно-десятичной
  нотации.
- Случайные числа берутся из `rand()` с инициализацией через `time(nullptr)`;
  это имитация, а не криптостойкий генератор. Распределение адресов
  равномерное по всему диапазону `0.0.0.0`–`255.255.255.255`, поэтому при
  узкой маске доля «своих» пакетов мала — это ожидаемо.
- Маска не проверяется на «непрерывность» (что старшие биты единицы, младшие
  нули); используется как есть в операции `&`.
- Реальной отправки пакетов нет — только расчёт статистики.
